# TurtleBot3 牛耕式完全覆蓋路徑規劃 (CCPP) 專案設計架構

本專案實作於 ROS Noetic 環境，使用 TurtleBot3 Burger 機器人，目標是在封閉的方形空間內執行「牛耕式演算法 (Boustrophedon Algorithm)」以實現完全覆蓋搜索。

---

## 1. 系統環境與硬體
*   **作業系統**: Ubuntu 20.04 (ROS Noetic)
*   **硬體平台**: TurtleBot3 Burger
*   **關鍵感測器**: 360° LiDAR (LDS-01)
*   **定位與建圖**: Gmapping SLAM (提供 `/map` 與 `map` -> `odom` TF 轉換)

---

## 2. 軟體模組架構

### A. 地圖處理與伺服器模組 (`map_server.py`)
作為系統的核心樞紐，負責資料處理與跨執行緒管理：
*   **資料訂閱**: 接收 `/map` (OccupancyGrid) 與 `/odom` (Odometry)。
*   **形態學處理**: 
    *   **侵蝕 (Erosion)**: 縮小障礙物，用於確認機器人中心可安全到達的範圍。
    *   **膨脹 (Dilation)**: 擴大障礙物，用於產生網頁上顯示的安全緩衝地圖。
*   **路徑追蹤**: 即時記錄機器人座標並生成足跡軌跡圖。
*   **執行緒安全**: 使用 `threading.Lock` 保護地圖資料與機器人狀態，確保 Flask 讀取時不會與 ROS 回呼函數產生衝突。

### B. 路徑規劃模組 (`boustrophedon.py`)
實作牛耕式覆蓋演算法的核心邏輯：
*   **PCA 方向對齊**: 利用主成分分析 (Principal Component Analysis) 找出自由空間的長軸與短軸，自動將掃描線與房間主軸對齊，避免地圖傾斜導致覆蓋效率下降。
*   **掃線生成**: 根據設定的掃描間距 (Spacing) 產生「來回」的路點。
*   **安全邊距**: 考慮機器人半徑，確保規劃路徑不與牆面碰撞。
*   **輸出**: 將路徑以 `nav_msgs/Path` 格式發布至 `/coverage_path`。

### C. 網頁呈現模組 (Flask + Web)
提供使用者視覺化介面：
*   **Flask 後端**: 實作於 `map_server.py` 內，提供靜態資源與 API 介面。
*   **地圖層疊呈現**: 透過 HTML5 Canvas 或多層圖形渲染，將原始地圖、侵蝕/膨脹圖層與機器人軌跡重疊顯示。
*   **控制指令**: 提供按鈕觸發 `/coverage/start` 與 `/coverage/stop` API，啟動或中斷任務。

### D. 移動執行模組 (move_base)
*   負責實際執行路徑點的導航。
*   接收從 `map_server.py` 發出的目標點 (Goal)，並透過局部路徑規劃器 (DWA) 避障移動。

---

## 3. 啟動流程與設定 (`start.launch`)

啟動檔整合了所有硬體與軟體組件，流程如下：

1.  **環境變數設定**: 自動設置 `TURTLEBOT3_MODEL=burger`。
2.  **硬體驅動**: 啟動 `turtlebot3_robot.launch` 與實體機器人建立連線。
3.  **SLAM 建圖**: 
    *   啟動 `gmapping` 進行即時掃描與定位。
    *   同時發布 `/map` 供路徑規劃使用，並發布 `map -> odom` TF 供 `move_base` 定位。
4.  **導航堆疊**: 
    *   載入 `move_base` 節點。
    *   自動套用 `turtlebot3_navigation` 的標準參數 (DWA Planner, Costmap params)。
5.  **應用層節點**: 啟動 `map_server.py` 開放 8080 埠位提供網頁監控與任務派送。

---

## 4. 座標系說明
*   **`map`**: 全域地圖座標系，所有路徑規劃均以此為基準。
*   **`odom`**: 里程計座標系，提供短時間內的高頻率位姿更新。
*   **`base_footprint`**: 機器人底座中心，投影於地面。

---

## 5. 實作細節亮點
*   **PCA 地圖對齊技術**: 解決 `/map` 產生的地圖可能因建圖初期的航向誤差而產生傾斜的問題。若掃描線與房間牆壁不平行，會導致「階梯狀」的覆蓋路徑，大幅降低效率並增加轉彎次數。本專案透過 PCA 計算所有空地格的協方差矩陣，找出環境的主成分向量（長軸與短軸），強制讓牛耕掃描線沿著環境長軸進行規劃，確保覆蓋路徑與牆面平行。
*   **動態裁切**: 地圖伺服器會自動偵測地圖邊界並進行裁切，減少網頁傳輸頻寬與顯示多餘空白。
*   **異步執行**: 牛耕式規劃與執行採用獨立執行緒處理，不會阻塞 ROS 的訊息處理迴圈。
*   **失敗容錯**: `move_base` 執行時若無法到達目標，系統會記錄狀態並嘗試執行下一個點，確保任務持續進行。
