開機自動建圖：要做什麼、怎麼做、為什麼這樣能動

目標：車子一上電，不用碰手機、不用開電腦，自己把整個場地的地圖畫出來，畫完自己停下並存檔。 本文用白話說明，搭配本專案現有的程式（launcher.py、map_server.py、start.launch）講要改哪裡。

1一句話總結：現在差在哪

「開機自動建圖」其實是兩件事拼起來：

① 開機自動「開系統」 現在：上電後車上控制台（port 8000）會自己跑起來，但要你在手機上按「啟動系統」才會開始。
要做：控制台開機後，等硬體準備好就自己按下啟動。
② 自動「建圖」 現在：SLAM 會開起來，但地圖要你用搖桿把車開著繞一圈才畫得出來。
要做：讓車子自己決定下一步要去哪裡看，一直走到沒有沒看過的地方為止。

第 ① 件很簡單，改控制台就好。第 ② 件是重點，業界標準做法叫 Frontier（邊界）探索： 地圖上「已經看過的空地」跟「還沒看過的區域」交界的那條線，就是邊界；車子只要一直往邊界走，邊界後面的東西就會被光達看到、補進地圖。 邊界全部消失，就代表整個場地都看過了。

1

2會用到的套件

大部分你車上都已經有了（之前同步時查過已安裝的 ros-noetic-*），真正要新裝的只有探索套件。

套件狀態白話：它負責什麼
turtlebot3_bringup已安裝 開底盤和光達。它會跟底盤板 OpenCR 講話（讀輪子轉了多少、把速度指令送給馬達），並把光達資料發成 /scan。
turtlebot3_slam + gmapping已安裝 SLAM＝「邊走邊畫地圖、同時知道自己在地圖哪裡」。輸入光達＋輪子里程，輸出地圖 /map。
move_base + dwa_local_planner已安裝 導航。你給它一個目的地，它負責規劃路線、閃障礙、控制速度開過去。覆蓋任務現在就是靠它。
turtlebot3_navigation已安裝 只拿它的參數檔（車身大小、速度上限、障礙膨脹範圍），start.launch 已經在用。
explore_lite要新裝 Frontier 探索。讀地圖、找出所有邊界、挑一個最划算的，丟給 move_base 去開。到了或卡住就換下一個。
安裝：sudo apt install ros-noetic-explore-lite
map_server（ROS 官方的）確認一下 用它附的 map_saver 把地圖存成 .pgm + .yaml。通常隨 navigation 一起裝好， 用 rospack find map_server 確認；沒有就 sudo apt install ros-noetic-map-server。
本專案 launcher.py要修改 加「開機自動啟動」開關與「等硬體就緒」。
本專案 map_server.py要修改 加「探索模式」：啟動／停止 explore_lite、判斷探索完成、存圖、回起點；並和遙控、覆蓋互斥。
本專案 launcher.html要修改 手機頁加「自動建圖」按鈕、進度、「開機自動建圖」開關。
名字撞到要小心 ROS 官方有一個套件叫 map_server（存讀地圖用），我們專案的網頁節點檔名也叫 map_server.py、節點名稱 /map_server。 用 map_saver 存圖沒問題（它的節點名稱是 map_saver），但不要再另外啟動官方的 map_server 節點，否則節點名稱相同，先開的會被踢掉。

3工作原理（白話版）

3-1 資料怎麼流

把整台車想成一條生產線：眼睛（光達）看到牆 → 畫圖員（SLAM）把牆畫進地圖 → 探險隊長（explore_lite）看地圖決定下一站 → 司機（move_base）規劃路線、控制方向盤 → 腳（OpenCR 底盤）轉輪子。車子一動，光達看到新的東西，整條線再跑一次。

3-2 SLAM：地圖怎麼畫出來

地圖是一張格子紙，每格 5 公分，每格只有三種狀態：

空地（看過、沒東西） 障礙（看過、有東西） 未知（還沒看過）

光達每秒轉 5 圈，每圈量 360 個方向「多遠有東西」。雷射打到的那一格塗黑，雷射一路經過的格子塗白。 難的地方是「車子現在到底在哪」：輪子會打滑，里程會越算越歪。gmapping 的做法是同時猜很多個「車子可能的位置」（粒子）， 每個猜測都拿這一圈光達去比對地圖，比對得越吻合的猜測越可信，不吻合的淘汰。這樣地圖和位置會互相校正，不會越畫越歪。

3-3 Frontier 探索：車子怎麼知道要去哪

explore_lite 大約每 3 秒做一次這四步：

  1. 找邊界格：掃整張地圖，凡是「自己是空地、旁邊有未知格」的，就是邊界格（圖中橘色）。
  2. 分群：相連的邊界格算同一段邊界。太短的（例如小於 0.3 公尺，比車還窄）直接丟掉，因為那通常是雜訊或車子鑽不進去的縫。
  3. 打分數：分數 ≈ 邊界越長越好 − 離車子越遠越扣分。意思是「又近又大片」的未知區最值得去。
  4. 派車：把分數最高那段邊界的中心點丟給 move_base 當目的地。開到附近時，光達已經看到原本未知的那片，邊界自然往後退或消失 → 回到第 1 步。

如果某個目標一直開不到（例如 30 秒都沒有進展），explore_lite 會把它列入黑名單、改去下一個。 當地圖上再也找不到夠大的邊界，它就停止派車——這就是「探索完成」。

3-4 move_base：司機怎麼開

move_base 拿到目的地後分兩層處理：全域規劃（navfn）在整張地圖上找一條不撞牆的路，像導航 App 畫路線； 區域規劃（DWA）每秒試算很多種「速度＋轉向」組合，挑一個既沿著路線、又不會撞到眼前障礙的，送給輪子。 地圖上的牆會被「加厚」（膨脹），讓路線跟牆保持距離。這套跟你的覆蓋任務用的是同一個 move_base。

3-5 開機自動：誰叫誰起床

Linux 開機後由 systemd 負責把該開的服務一個一個叫起來，我們的 ccpp-launcher.service 已經登記在裡面。 新增的部分是：控制台起來後，先確認三件事都好了才啟動 ROS——

  • /dev/ttyACM0 出現了（底盤板 OpenCR 的 USB）
  • /dev/ttyUSB0 出現了（LDS 光達的 USB）
  • 拿到網路 IP（ROS 需要用 IP 讓節點互相找到）

沒等就直接開，常見的結果是 turtlebot3_core 連不上 OpenCR、光達沒資料，整套卡住。所以「等硬體」是開機自動化最重要的一步。

4實作步驟（要改哪些檔案）

設計原則：沿用現在管 SLAM 的方式 現在 map_server.py 是用「子行程」開關 SLAM 的（slam_launch()／slam_kill()），網頁才能「重新建圖」。 探索也照這個模式：由 map_server 開關 explore_lite。好處是 map_server 永遠知道「現在是不是在探索」， 就能擋住探索中有人按搖桿或按「開始覆蓋」（兩個人同時搶方向盤是最危險的狀況）。
  1. 車上安裝套件 
    sudo apt update
sudo apt install ros-noetic-explore-lite ros-noetic-map-server
rospack find explore_lite        # 有印出路徑就是裝好了

    只要做一次。裝在車上，不屬於專案程式，不用同步。

  2. 先手動試一次 explore_lite（不改任何程式）

    用手機按「啟動系統」，等地圖出現後，在車上另開一個終端機：

    rosrun explore_lite explore _robot_base_frame:=base_footprint \
    _costmap_topic:=map _costmap_updates_topic:=map_updates \
    _visualize:=false _planner_frequency:=0.33 _progress_timeout:=30.0 \
    _potential_scale:=3.0 _gain_scale:=1.0 _min_frontier_size:=0.3

    車子應該會自己開始走。這一步先確認「套件本身在你的場地能動」，再開始寫程式，出問題比較好查。 按 Ctrl+C 停止。

    參數白話 costmap_topic:=map 直接看 SLAM 的地圖找邊界；planner_frequency 0.33 每 3 秒重新挑一次目標； progress_timeout 30 30 秒沒進展就放棄這個目標；potential_scale 越大越在意「近」， gain_scale 越大越在意「大片」；min_frontier_size 小於這長度（公尺）的邊界不理它。
  3. 改 map_server.py：加「探索模式」

    新增的東西照現有 SLAM 管理的寫法放在同一區。

    • explore_launch()／explore_kill()：跟 slam_launch() 一樣，用 subprocess.Popen(..., preexec_fn=os.setsid) 開 explore_lite，停止時送 SIGINT。
    • 狀態：cov_status['state'] 多一種 'exploring'。現有的互斥規則是「不是 running 就能遙控」，要改成「running 和 exploring 都不能遙控、也不能開始覆蓋」。
    • 新路由：POST /explore/start、POST /explore/stop，/coverage/status 多回傳探索進度。
    • 判斷探索完成：在 map_callback() 已經拿到地圖陣列，順手數「邊界格」有幾個（空地且四周有未知）。 連續 20 秒都少於門檻（例如 10 格），或已知面積 60 秒都沒有增加，就判定完成。自己算比去讀 explore_lite 的訊息可靠，網頁也能顯示「剩幾段邊界」。
    • 完成後：停 explore_lite → 存圖（下一步）→ 送 move_base 目標回到起點 (0, 0) → 狀態回到 idle，可以接著按「開始覆蓋」。
    • 參數：加 ~auto_explore（預設 false）。為 true 時，SLAM 開好、第一張地圖進來後等 10 秒自動 explore_launch()。
    # 判斷邊界格的核心只要幾行（free/unknown 是由 /map 轉成的布林陣列）
from scipy.ndimage import binary_dilation
frontier = free & binary_dilation(unknown)      # 自己是空地、旁邊碰到未知
n_frontier = int(frontier.sum())
  4. 存地圖 
    rosrun map_server map_saver -f ~/catkin_ws/src/turtlebot3_ccpp/maps/explore_20261110_153000

    在 map_server.py 裡用 subprocess.run() 呼叫，檔名用時間戳。會產生 .pgm（地圖影像）和 .yaml（解析度、原點）。 maps/ 已經在 .gitignore，也不在同步範圍，不會被同步腳本刪掉。

  5. 改 start.launch：把開關傳下去 
    <arg name="auto_explore" default="false" />
...
<node pkg="turtlebot3_ccpp" type="map_server.py" name="map_server" output="screen">
    ...
    <param name="auto_explore" value="$(arg auto_explore)" />
</node>

    手動啟動時預設不探索，行為跟現在一樣；只有 auto_explore:=true 才會自己跑。

  6. 改 launcher.py：開機自動啟動
    • 設定檔 ~/.ros/ccpp_launcher/config.json，例如 {"autostart": true, "auto_explore": true, "model": "burger"}。 放在車上家目錄，不放專案資料夾，同步程式時不會被蓋掉。
    • 控制台啟動時讀設定；autostart 為 true 就開一條執行緒：每秒檢查 /dev/ttyACM0、/dev/ttyUSB0、IP， 全部就緒後再多等 5 秒，呼叫現有的 start()，多帶 auto_explore:=true。最多等 3 分鐘，等不到就放棄並在頁面上顯示原因。
    • 新增 GET/POST /api/config 讓手機能切換開關。
  7. 改 launcher.html：手機上看得到、關得掉
    • 「操作」頁：自動覆蓋上方加「自動建圖」卡片：開始／停止按鈕、已知面積、剩餘邊界數、探索時間。
    • 頂端三步驟的「② 遙控建圖」改成「② 建圖」，提示文字依狀態寫「自動建圖中…」。
    • 「系統」頁：加兩個開關「開機自動啟動系統」「啟動後自動建圖」。
  8. commit → push → 同步到車上 → 補 devlog 
    git add scripts launch web
git commit -m "feat(explore): 開機自動建圖（frontier 探索）"
git push origin rebuild
bash tools/sync_to_robot.sh

5安全與防呆

開機就會自己跑，代表可能沒有人在旁邊。以下幾條建議一起做：

風險白話對策
一上電就衝出去放在桌上充電、搬運途中開機，車子突然開始走 開機自動建圖預設關閉，要在手機上主動打開；開始探索前等 10 秒、手機頁顯示倒數，可按停止。
兩個人搶方向盤探索中又按搖桿或開始覆蓋 map_server 用 exploring 狀態擋掉遙控與覆蓋（同現在覆蓋中鎖搖桿的做法）。
永遠走不完門沒關、場地有出口，未知區一直有 設最長探索時間（例如 10 分鐘）與最大距離起點範圍，超過就停止並存圖。
電池耗盡Burger 的電池約 11.1 V，低於約 11 V 就該停 控制台已經在讀電壓；低於門檻就停止探索、存圖、提示充電。
撞到東西光達只看得到約 12 公分高度那一圈，矮的東西看不到 探索時把速度上限調低（DWA 的 max_vel_x），場地先清掉低矮雜物；第一次測試一定要有人在旁邊。
地圖畫歪開太快、轉太急時 SLAM 容易對不上 同上，降低速度與角速度；長走廊、空曠大廳特徵少，容易歪，屬於 gmapping 的天生限制。

6怎麼測試

  1. 先手動跑 explore_lite（第 4 章第 2 步），確認車子在你的場地會自己走、會停。
  2. 網頁按鈕觸發探索：還沒開機自動，先用手機按「自動建圖」，確認可以中途停止、停止後搖桿恢復可用。
  3. 完成判定：小場地（例如用紙箱圍 2 m × 3 m 長方形）跑到結束，確認會停、會存圖、會回起點。
  4. 開機自動：打開開關後重開機（手機頁「重新開機」），從上電計時，記錄「多久開始動」「多久完成」。
  5. 異常情況：拔掉光達 USB 開機（應該等待並顯示原因、不會亂跑）；探索中按停止；探索中電壓過低（可以暫時把門檻調高來模擬）。
  6. 每一次測試的結果寫進 docs/05_開發日志/CHANGELOG.md。

7常見問題

Q：為什麼不自己寫探索演算法？

找邊界本身很簡單（第 4 章的三行），難的是「目標開不到怎麼辦、要不要換、什麼時候放棄」這些細節。 explore_lite 已經處理好又很輕量（它不自己算 costmap，直接讀現有地圖），在樹莓派上跑得動。我們只自己寫「判斷完成」，因為要顯示進度、決定何時存圖。

Q：建完圖可以直接接著自動覆蓋嗎？

可以。探索完成後狀態回到 idle，地圖和車子位置都還在，按「開始」就會用這張地圖規劃覆蓋路徑。 之後也可以做成「建完圖自動開始覆蓋」，但建議先人工確認地圖沒歪再按。

Q：場地是正方形可以嗎？

建圖沒問題；但覆蓋規劃用 PCA 找主軸，正方形會讓主軸方向不穩定，覆蓋效果退化。建圖跟覆蓋是兩件事，這點不影響本文的探索。

Q：IP 變了怎麼辦？

控制台每次啟動都會用車子當下的 IP 設定 ROS，自動啟動也一樣，所以換熱點不用改設定；只是手機要用新 IP 開頁面。

Q：探索中想停下來怎麼辦？

手機頁「停止」會讓 map_server 收掉 explore_lite 並送零速度；或直接在「系統」頁停止整套系統。 後端本來就有「0.6 秒沒收到指令就停車」的保護，但那是給遙控用的；探索是 move_base 在開，所以一定要從頁面按停止。
