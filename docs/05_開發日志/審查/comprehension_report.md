# 第 6 階段：理解度測試（Comprehension Test）報告

- **目標**：`README.md`，FeatureRange 第 1–53 行；DetailedRange 不適用
- **審查員**：`egm-comprehension`（只讀 README，不給背景檔案、不套標準）
- **結論**：審查員寫得出 paraphrase，所以沒有 Blocker。但 README 不是自足的文件：7 項 Major、5 項 Nit。

**What this proposes**

這份 README 是一個 TurtleBot3 機器人專案的入口頁。專案做「牛耕式完全覆蓋路徑規劃」（CCPP）：機器人先自動建圖，再沿來回的直線掃過整個區域。文件記錄到 2026-11-11 收工時的狀態。手機控制台、自動建圖、SLAM 調參、直線循跡加外圈都已在實車驗證過，最近一次覆蓋率 97.7%。新改的「跨區移動」（`_drive_to`，自己開直線或借 move_base 算路線，DWA 只當備援）已經上車，但還沒實車測過。文件接著列下次要做的驗證步驟、資料夾結構、改程式後怎麼同步到車上，以及怎麼用手機打開控制台。

**How the existing system works, per this document**

程式全部放在 `turtlebot3_ccpp/`，和車上的 `~/catkin_ws/src/turtlebot3_ccpp` 一對一對應。`launcher.py` 在 :8000 提供控制台，開機自動執行。`map_server.py` 是主節點，用 :8080。`coverage_planner.py` 放演算法。開發流程是：本機改程式，在 CHANGELOG 補一筆，commit 並 push，再用 `sync_to_robot.sh` 只把已 commit 的內容送上車。改到 launch 或 SLAM／move_base 參數時，要在手機「系統」頁停止再啟動才會生效。執行紀錄（`maps/`、`data/`）在車上產生，不進版控。

※ 審查員說明：第二段多處是推測的。例如 :8000 和 :8080 兩個服務的分工、`index.html` 由誰提供，文件都沒寫清楚。

## 主持人註記：和第 5 階段有一處衝突

第 5 階段建議把參數數值、事件字串等細節**移出** README（Z3）。第 6 階段卻因為這些名詞**沒有定義**而判 Major（#4–#6）。兩邊不能都照做，建議的處理方式是：README 下一步改寫成目的層級，例如「確認跨區移動不再受困」，具體參數和指令只放在架構說明裡，README 用連結直接指到該章。這樣兩個問題都能解決，不必把定義搬進 README。

另外，#1、#2、#7 和第 5 階段的 Z1 是同一個問題：README 沒有自足的概述和操作入口。
