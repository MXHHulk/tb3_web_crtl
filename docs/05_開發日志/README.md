# 05_開發日志

本資料夾記錄 **每一次程式修改** 的開發日志（devlog）。
目的：日後回頭看時，能清楚知道「**動了什麼、為什麼動、改了哪些檔案、結果如何**」，
而不必逐一比對 git diff。

## 資料夾結構

```
docs/05_開發日志/
├── README.md       本說明檔（撰寫規範）
└── CHANGELOG.md    開發日志主檔（時間倒序，最新的在最上面）
```

> 與 git commit 的差異：commit message 只寫「一句話摘要」，
> 日志則要把**動機、做法、踩到的坑、待辦**都記清楚，給未來的自己看。

## 撰寫規範

1. **每次修改程式碼都要新增一筆日志**，寫在 `CHANGELOG.md` 最上方（時間倒序）。
2. 一筆日志對應「一個有意義的改動單位」，通常等於一次 commit。
3. 用下列模板，欄位不適用時寫「無」，不要直接刪欄位。

### 日志模板

```markdown
## YYYY-MM-DD　<一句話標題>

- **類型**：feat / fix / refactor / tune / docs / chore（對應 git 規範）
- **動了什麼**：條列實際修改的內容
- **為什麼**：這次改動的動機 / 想解決的問題
- **影響檔案**：
  - `path/to/file` — 改了什麼
- **結果 / 驗證**：跑了什麼、結果如何（或「尚未驗證」）
- **待辦 / 已知問題**：後續要處理的事（無則寫「無」）
```

## 分類標籤（類型）

沿用 [`../06_規範/GIT_CONVENTION.md`](../06_規範/GIT_CONVENTION.md) 的定義：

| 類型 | 使用時機 |
|------|----------|
| `feat` | 新增功能 |
| `fix` | 修正 Bug |
| `refactor` | 重構，不改變行為 |
| `tune` | 調整 ROS 參數或演算法數值 |
| `docs` | 只改註解或文件 |
| `chore` | 環境、設定、相依套件調整 |
