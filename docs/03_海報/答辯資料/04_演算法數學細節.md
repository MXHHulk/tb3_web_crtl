## 一、安全邊距膨脹（`apply_safety_margin`）

**問題**：路徑規劃是把機器人當成「一個點」在算，但實體車有 0.20 m 直徑，貼牆的路徑會撞。

**做法**：與其縮小機器人，不如**放大障礙物**（Minkowski 和的標準技巧）。

```python
obs  = data == 100                       # 障礙格的布林遮罩
r    = max(1, round(margin / resolution))  # 0.10 / 0.05 = 2 格
kern = np.ones((2*r+1, 2*r+1), dtype=bool) # 5×5 結構元素
safe = binary_dilation(obs, structure=kern)
free = (data == 0) & ~safe               # 真正可走 = 是空地 且 不在膨脹區
```

**數學意義**：`binary_dilation(A, B) = { a + b | a ∈ A, b ∈ B }`。用 5×5 方形核，等於把每個障礙格往外長 2 格（0.10 m）。

**兩個要注意的**：

- 用 `data == 0` 而非 `data != 100`：**未知格（−1）不算可走**。這是保守設計，地圖沒建完的區域不會被排進路徑。
- 方形核（chebyshev 距離）比圓形核多膨脹一點角落，偏保守，對安全有利。

## 二、PCA 主軸對齊（`boustrophedon` 前半）

**問題**：地圖座標系的方向由機器人**開機當下的朝向**決定，跟房間牆面沒有任何關係。若沿地圖 x 軸掃一個斜的房間，掃描線末端會被牆切成階梯狀鋸齒，轉彎暴增、邊角漏掃。

**做法**：讓**環境自己決定**掃描方向。

### 推導

設可走格的世界座標點集 $P = \{p_1, \dots, p_N\}$，$p_i \in \mathbb{R}^2$。

1. **去中心化**
   $$\bar p = \frac{1}{N}\sum_i p_i, \qquad d_i = p_i - \bar p$$

2. **共變異數矩陣**（2×2 對稱半正定）
   $$C = \frac{1}{N-1}\sum_i d_i d_i^\top = \begin{bmatrix} \sigma_{xx} & \sigma_{xy} \\ \sigma_{xy} & \sigma_{yy}\end{bmatrix}$$

3. **特徵分解** $C v = \lambda v$。因 $C$ 對稱，兩個特徵向量必**正交**，且特徵值皆為實數非負。

4. **取軸**
   - $\lambda_{\max}$ 對應的 $v_{\max}$ = **長軸**（自由空間變異最大的方向）→ 當**掃描方向**
   - $\lambda_{\min}$ 對應的 $v_{\min}$ = **短軸**（正交）→ 當**換行方向**

**為什麼最大特徵向量就是長軸**：$v^\top C v$ 是點集投影到單位向量 $v$ 上的變異數。最大化這個變異數的 $v$ 就是 $\lambda_{\max}$ 的特徵向量（Rayleigh 商）。房間最長的方向，投影後散得最開，變異數最大。

### 程式對應

```python
center           = pts.mean(axis=0)
diffs            = pts - center
eigvals, eigvecs = np.linalg.eigh(np.cov(diffs.T))   # eigh：對稱矩陣專用，回傳已排序
axis_a = eigvecs[:, np.argmax(eigvals)]   # 長軸 = sweep
axis_b = eigvecs[:, np.argmin(eigvals)]   # 短軸 = step
if axis_a[0] < 0: axis_a = -axis_a        # 固定正負號，避免路徑方向隨機翻轉
if axis_b[1] < 0: axis_b = -axis_b
```

> 用 `np.linalg.eigh` 而不是 `eig`：共變異數矩陣保證對稱，`eigh` 更快且保證回傳實數解。
> **符號固定**很重要——特徵向量差一個負號仍是合法解，不固定的話每次重新規劃路徑起點會左右亂跳。

### 幾何直覺（可畫在白板）

```
   固定水平掃（錯）           PCA 對齊掃（本專案）
   ┌──────────┐              ┌──────────┐
   │ ─ ─ ─ ─  │ 斜房間       │ ╲ ╲ ╲ ╲  │ 貼齊長軸
   │─ ─ ─ ─   │ 切成階梯     │  ╲ ╲ ╲ ╲ │ 線最少、轉彎最少
   │ ─ ─ ─ ─  │ 漏邊角       │ ╲ ╲ ╲ ╲  │
   └──────────┘              └──────────┘
```

## 三、牛耕路點生成（`boustrophedon` 後半）

**做法**：把每個可走點投影到兩個軸上，沿短軸每隔一個間距切一條「帶」，取該帶在長軸上的兩端點。

```python
proj_a = diffs @ axis_a        # 每個點在長軸上的位置（純量）
proj_b = diffs @ axis_b        # 每個點在短軸上的位置

b = proj_b.min() + spacing/2   # 第一條線內縮半個間距
while b <= proj_b.max() + spacing/2:
    mask = np.abs(proj_b - b) < spacing/2      # 落在這條帶裡的點
    if mask.any():
        a_vals  = proj_a[mask]
        p_start = center + a_vals.min()*axis_a + b*axis_b   # 帶的一端
        p_end   = center + a_vals.max()*axis_a + b*axis_b   # 另一端
        waypoints += [p_start, p_end] if l2r else [p_end, p_start]  # 方向交替
        l2r = not l2r
    b += spacing
```

**三個設計重點**：

1. **只取兩端點，不逐格輸出**：一條掃描線只產生 2 個路點，交給 move_base 去走直線。路點少 → 送 goal 的次數少 → 執行順暢。
2. **方向交替（`l2r = not l2r`）**：這就是「牛耕」的定義——像牛犁田來回走，走完一條接著回頭走下一條，不用空跑回起點。
3. **`if mask.any()` 跳過空帶**：帶裡沒有可走點（例如中間有大障礙）就直接跳過，不會產生無效路點。

**產出**：`[(world_x, world_y), ...]` 世界座標路點串列，直接可送 move_base。

## 四、複雜度與效能

| 步驟 | 複雜度 | 說明 |
|---|---|---|
| 安全邊距膨脹 | O(HW · k²) | SciPy 的 `binary_dilation`，C 實作 |
| `np.where(free)` | O(HW) | 取出所有可走格 |
| PCA | **O(N)** + O(1) | 共變異數是 N 個 2×2 外積累加；特徵分解是固定的 2×2 |
| 投影 | O(N) | 兩次矩陣乘向量 |
| 切帶迴圈 | O(L · N) | L = 掃描線數（典型 20–50 條） |

**全程 NumPy 向量化，沒有逐格 Python 迴圈**。上萬格的地圖也在毫秒級算完——這是「收到新地圖就能即時重新規劃」的基礎。

被問「為什麼不用 A*／Dijkstra 規劃覆蓋」→ 那些是**點對點**最短路徑演算法，解的是不同問題；覆蓋要的是「走遍所有格」，本質上接近 TSP／中國郵差問題。牛耕式是用幾何結構把它降成 O(N) 的近似解。

## 五、這個方法的數學前提（誠實面對）

PCA 假設自由空間**大致是一個凸的、單一主軸明顯的區域**。

- **成立**：長方形、正方形（任意朝向）、稍微不規則的單一房間 → 效果好，這也是海報主打的「任意方向四邊形」。
- **不成立**：L 形、口字形、多房間 → PCA 算出的主軸是「全體點的平均方向」，對某些分支不是最佳，可能出現長距離空跑。
- **正解是什麼**：先做 **boustrophedon cell decomposition**（Choset & Pignon 1998）把空間切成多個凸胞元，每個胞元各自 PCA + 牛耕，再用 TSP 決定胞元走訪順序。**這是我們列在未來工作的第一項**（見 [06_已知限制與未來工作.md](06_已知限制與未來工作.md)）。
