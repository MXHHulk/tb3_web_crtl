# 參數速查與選擇理由

> 被問到任何數字，直接翻這頁。
> **分成兩類：「我們自己定的」要說得出理由；「官方預設」老實說沒調過。**

---

## 一、我們自己定的參數（要說得出理由）

### `scripts/coverage_planner.py`

| 參數 | 值 | 為什麼是這個值 |
|---|---|---|
| `SPACING` | **0.18 m** | 機器人覆蓋寬度約等於車寬 0.20 m。間距取 0.18 = 覆蓋寬度的 90%，**刻意留 10% 重疊**，讓相鄰兩條掃描線不會因為定位誤差而中間留一條沒掃到的縫 |
| `MARGIN` | **0.10 m** | ≈ 機器人半徑（直徑 0.20 m）。路徑是給「點機器人」規劃的，先把障礙物往外膨脹一個半徑，規劃出來的線就等於實體車身不會擦牆 |
| 膨脹核大小 | `2r+1 = 5×5` 格 | `r = round(MARGIN / resolution) = round(0.10/0.05) = 2` 格，故 5×5 |
| 第一條掃描線位置 | `b_min + SPACING/2` | 從邊界往內縮半個間距，讓兩側邊緣的覆蓋量對稱，不會一邊貼牆一邊空一大條 |

### `scripts/map_server.py`

| 參數 | 值 | 說明 |
|---|---|---|
| `MORPH_ITER` | **2** | 網頁侵蝕／膨脹圖層的迭代次數。3×3 核跑 2 次 ≈ 半徑 2 格 = 0.10 m ≈ 機器人半徑，避免把窄出口畫成封死 |
| `CROP_PAD` | **10 格** | 地圖自動裁切時保留的邊距（= 0.5 m），免得剛好切齊牆面看起來很擠 |
| 軌跡取樣門檻 | **0.1 m** | `odom_callback` 每移動 0.1 m 才記一點（判斷式是 `dx²+dy² >= 0.01`），避免原地抖動塞爆陣列 |
| 軌跡上限 | **10000 點** | 超過就丟最舊的（≈ 走過 1 km），防止記憶體無限成長 |
| HTTP 埠 | **8080** | `start.launch` 的 `port` 參數可改：`roslaunch turtlebot3_ccpp start.launch port:=9000` |
| move_base 等待 | **5 秒** | `wait_for_server(Duration(5.0))`，逾時就回報「move_base 未啟動」而不是無限卡住 |
| 停止訊號檢查 | **每 0.5 秒** | `wait_for_result(Duration(0.5))` 迴圈，讓「停止」按鈕最慢 0.5 秒內生效 |
| TF 查詢逾時 | **0.05 秒** | `/scan` 路由查 `map←base_scan`，查不到就回空陣列，絕不阻塞網頁 |

### `web/index.html`

| 參數 | 值 | 說明 |
|---|---|---|
| 一般輪詢 | **1 Hz**（`setInterval(refresh, 1000)`） | 地圖、機器人位置、軌跡、覆蓋狀態 |
| 雷射輪詢 | **5 Hz**（`setInterval(refreshScan, 200)`） | 對齊 LDS-01 的 5 Hz，才看得到掃描即時跳動 |
| 圖層數 | **7** | 原始地圖、侵蝕層、膨脹層、覆蓋路徑、行走軌跡、雷射掃描、機器人 |

## 二、地圖相關（gmapping 給的，不是我們定的）

| 參數 | 值 | 說明 |
|---|---|---|
| 地圖解析度 | **0.05 m/格** | gmapping 預設。所有「公尺 ↔ 格」換算都用它：`格數 = 公尺 / 0.05` |
| 柵格值 | `0` 空地、`100` 障礙、`-1` 未知 | `nav_msgs/OccupancyGrid` 標準 |
| 更新頻率 | 約 0.5–1 Hz | 依 `map_update_interval` 與機器人移動量而定；`map_server.py` 每 2 秒會印一次實測平均 Hz |

## 三、官方預設值（我們沿用未調，被問就老實說）

> 全部來自 `turtlebot3_navigation/param/*.yaml` 與 `turtlebot3_slam` 的 launch。
> **以下數值請在自己機器上用 `rosparam get` 確認後再引用**，不同版本會有差異。

### move_base / DWA（`dwa_local_planner_params_burger.yaml`）

| 參數 | 典型值 | 意思 |
|---|---|---|
| `max_vel_x` | 0.22 m/s | 最大前進速度（等於 Burger 硬體上限） |
| `min_vel_x` | −0.22 | 可倒退 |
| `max_vel_theta` | 2.75 rad/s | 最大轉速 |
| `acc_lim_x` / `acc_lim_theta` | 2.5 / 3.2 | 加速度上限 |
| `sim_time` | 1.5 s | DWA 每個候選速度往前模擬多久 |
| `vx_samples` / `vth_samples` | 20 / 40 | 速度取樣數，決定候選軌跡有幾條 |
| `path_distance_bias` | 32.0 | 「貼緊全域路徑」的權重 |
| `goal_distance_bias` | 20.0 | 「接近目標」的權重 |
| `occdist_scale` | 0.02 | 「遠離障礙」的權重 |
| `xy_goal_tolerance` | 0.05 m | 到達判定：位置誤差容忍 |
| `yaw_goal_tolerance` | 0.17 rad（≈10°） | 到達判定：角度誤差容忍 |

### costmap（`costmap_common_params_burger.yaml`）

| 參數 | 典型值 | 意思 |
|---|---|---|
| `robot_radius` | 0.105 m | move_base 自己的碰撞半徑（**跟我們的 MARGIN 0.10 是兩套獨立機制**） |
| `inflation_radius` | 1.0 m | costmap 膨脹層半徑（讓路徑傾向走中間） |
| local costmap 尺寸 | 3 × 3 m | 跟著機器人移動的視窗 |
| 更新頻率 | 10 Hz | |

### gmapping（`turtlebot3_gmapping.launch`）

| 參數 | 典型值 | 意思 |
|---|---|---|
| `particles` | 100 | 粒子數，越多越準也越吃 CPU |
| `maxUrange` | 3.0 m | 用於建圖的最大雷射距離（小於 LDS-01 的 3.5 m 上限） |
| `delta` | 0.05 | 地圖解析度 |
| `linearUpdate` / `angularUpdate` | 0.2 m / 0.2 rad | 移動多少才觸發一次更新 |
| `map_update_interval` | 2.0 s | 多久重新發布一次 `/map` |

**現場查法**：

```bash
rosparam get /move_base/DWAPlannerROS/max_vel_x
rosparam get /move_base/local_costmap/inflation_layer/inflation_radius
rosparam list | grep gmapping
```

## 四、三個「膨脹」不要搞混（最容易被問倒）

| 誰在膨脹 | 在哪 | 半徑 | 用途 |
|---|---|---|---|
| **規劃用安全邊距** | `coverage_planner.apply_safety_margin()` | `MARGIN = 0.10 m`（5×5 核） | **真的會影響路徑**：決定哪些格子算「可走」 |
| **網頁顯示圖層** | `map_server.map_callback()` | 固定 3×3 核 × 2 次 | **純視覺參考**，給人看的，不影響任何規劃 |
| **costmap inflation** | move_base 內部 | `inflation_radius = 1.0 m` | 影響 move_base 自己的局部避障，與上面兩者完全獨立 |

被問「你的膨脹半徑是多少」→ 先反問／先講清楚是問哪一個，這題答得出來很加分。
