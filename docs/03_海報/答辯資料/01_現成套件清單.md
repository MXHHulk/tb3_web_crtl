# 現成套件清單（海報 ③ 層的展開）

> 海報上只寫了四個名字：`gmapping`、`move_base + DWA`、`turtlebot3_bringup`、`tf2`。
> 但 `turtlebot3_bringup` 本身是一個「包裝」，底下還有三個節點；`move_base` 更是一整套。
> 被問「你用了哪些現成的東西」時，照這張表答。

---

## 一、一句話版本

> 我們用了 **6 個 ROS 套件**（bringup 驅動、rosserial、LDS 驅動、robot_state_publisher、gmapping、move_base）
> 和 **4 個 Python 函式庫**（NumPy、SciPy、Flask、Pillow）。
> 覆蓋路徑演算法與整套排程、網頁是我們自己寫的，沒有用任何現成的 CPP／coverage 套件。

---

## 二、由 `start.launch` 啟動的套件

### 1. `turtlebot3_bringup` — 硬體驅動包裝

`start.launch` 第 12 行 `include turtlebot3_robot.launch`。它自己不做事，只是把下面三個一起拉起來：

| 底下實際跑的節點 | 來自套件 | 做什麼 |
|---|---|---|
| `turtlebot3_core` | **`rosserial_python`**（`serial_node.py`） | 走 USB 序列跟 OpenCR 控制板對話，把板子算好的 `/odom`、`/joint_states`、`/imu`、`/battery_state` 轉成 ROS 訊息；同時把 `/cmd_vel` 送下去 |
| `turtlebot3_lds` | **`hls_lfcd_lds_driver`** | LDS-01 雷射雷達驅動，發布 `/scan`（`sensor_msgs/LaserScan`） |
| `robot_state_publisher` | **`robot_state_publisher`** + **`turtlebot3_description`**（URDF） | 讀 `/joint_states` 與 URDF，發布機器人各連桿的 TF：`base_footprint → base_link → base_scan / wheel_*` |

**發出**：`/scan`、`/odom`、`/joint_states`、`/imu`、`/tf`、`/tf_static`
**訂閱**：`/cmd_vel`

> 追問「odom 是誰算的」→ 不是這些套件算的，是 OpenCR 板上的韌體算完才傳上來。見 [02_硬體規格與里程來源.md](02_硬體規格與里程來源.md)。

### 2. `gmapping`（`slam_gmapping`）— SLAM 建圖與定位

`start.launch` 第 15 行，透過 `turtlebot3_slam.launch` 帶入，`slam_methods:=gmapping`。

- **它是什麼**：Grisetti 等人的 **RBPF（Rao-Blackwellized Particle Filter）** 式 SLAM。每個粒子帶一份自己的地圖與軌跡假設，用雷射掃描匹配（scan matching）評分後重採樣。
- **吃什麼**：`/scan` + `/odom` + TF（`base_footprint → base_scan`）。
- **吐什麼**：
  - `/map`（`nav_msgs/OccupancyGrid`，解析度 0.05 m/格，值 0=空地、100=障礙、-1=未知）
  - **`map → odom` 的 TF** ← 這條最關鍵，它就是「定位」：把 odom 累積的漂移修掉。
- **為什麼選它**：TurtleBot3 官方預設、2D 雷射 + 差速輪的標準組合、資源需求小（Raspberry Pi 跑得動）。Cartographer 精度更好但參數多、CPU 吃重。
- **在本專案的角色**：`/map` 是覆蓋規劃的**唯一輸入**；`map→odom` 讓 move_base 知道機器人在地圖上的哪裡。

---

### 3. `move_base` — 導航協調者（不是演算法本身）

`start.launch` 第 23–48 行，是唯一一個我們直接寫 `<node>` 起的外部節點。它**本身不規劃**，而是把五個外掛組裝起來跑一個狀態機：

| 組成 | 預設實作 | 做什麼 |
|---|---|---|
| **global planner** | `navfn/NavfnROS` | 在全域 costmap 上用 Dijkstra／A* 算一條「起點→目標」的粗路徑 |
| **local planner** | **`dwa_local_planner/DWAPlannerROS`**（我們在第 25 行明確指定） | 每個控制週期取樣一堆 (v, ω) 速度組合，模擬未來 1~2 秒的軌跡，用「貼近全域路徑／接近目標／遠離障礙」評分，選最高分那組送 `/cmd_vel` |
| **global costmap** | `costmap_2d` | 訂閱 `/map`（static layer）＋障礙層＋膨脹層（inflation） |
| **local costmap** | `costmap_2d` | 跟著機器人跑的小視窗（預設 3×3 m），只吃即時 `/scan`，負責閃突然出現的障礙 |
| **recovery behaviors** | 清 costmap、原地旋轉 | 卡住時的自救動作 |

- **對外介面是 action**（`move_base_msgs/MoveBaseAction`），不是 topic：可以回報進度、可以取消、有明確的成功／失敗狀態碼。
- **在本專案的角色**：只負責「從現在的位置走到我給的這一個點」。**它不會回答「怎麼走才能走遍整個房間」——那是我們寫的部分。**
- **參數來源**：全部沿用 `turtlebot3_navigation/param/*.yaml`，我們沒有調（見 [03_參數速查與選擇理由.md](03_參數速查與選擇理由.md)）。

> 常見追問「DWA 和 move_base 是同一個東西嗎」→ 不是。move_base 是協調者（狀態機 + costmap + 兩個 planner 插槽），DWA 是插在 local planner 那個插槽裡的**避障演算法**。

---

### 4. `tf2` / `tf2_ros` — 座標轉換樹

沒有獨立節點，是每個節點都連進去的函式庫。

- **維護什麼**：`map → odom → base_footprint → base_link → base_scan / wheel_left / wheel_right`
- **誰發布哪一段**：`map→odom` 由 gmapping；`odom→base_footprint` 由 OpenCR/rosserial；`base_link` 以下由 `robot_state_publisher`。
- **本專案怎麼用**：`map_server.py` 第 406 行開 `tf2_ros.TransformListener`，在 `/scan` 路由裡查 `map ← base_scan`，把雷射點從雷射座標系轉到地圖座標系，網頁上的紅點才會貼齊牆面。

---

### 5. `actionlib` — action 客戶端函式庫

`map_server.py` 第 196 行 `SimpleActionClient('move_base', MoveBaseAction)`。底層自動收發 `/move_base/goal`、`/cancel`、`/feedback`、`/status`、`/result`。

## 三、非 ROS 的 Python 函式庫

| 函式庫 | 用在哪 | 做什麼 |
|---|---|---|
| **NumPy** | `coverage_planner.py`、`map_server.py` | 柵格陣列運算、PCA 的 `np.cov` / `np.linalg.eigh`、向量化投影 |
| **SciPy**（`scipy.ndimage`） | `coverage_planner.py`、`map_server.py` | `binary_dilation`（安全邊距）、`binary_erosion`（網頁侵蝕圖層） |
| **Flask** | `map_server.py` | 內建 HTTP 伺服器與 9 條路由，跑在獨立執行緒（第 418 行） |
| **Pillow (PIL)** | `map_server.py` | 把灰階 NumPy 陣列存成 PNG bytes（第 73 行 `_to_png`） |

## 五、怎麼在現場自己查（被質疑時直接示範）

```bash
rosnode list                      # 現在跑了哪些節點
rosnode info /move_base           # 它的 pub/sub/action 全貌
rostopic list                     # 所有 topic
rostopic info /map                # 誰發布、誰訂閱
rosparam get /move_base/base_local_planner    # 確認 local planner 是 DWA
rosrun rqt_graph rqt_graph        # 節點連線圖（最有說服力）
rosrun tf2_tools view_frames.py   # 產生 TF 樹 PDF
```
